Recommending the next movie on a laptop GPU

✓ Beta 0.1 demo complete ✓ 12-combination benchmark complete One seed per combination

We built on eSASRec (ACM RecSys 2025), which found the most accurate combination of parts for a sequential recommendation model. We asked a question the paper doesn't: which combination gives the most accuracy for the least GPU memory and time on an ordinary laptop?

Experiment

Component benchmark

Tests every combination of 3 layer designs × 4 loss functions under the same 32-second training budget.

  • Measures accuracy, coverage, GPU memory, time and latency
  • Prints a detailed terminal report and saves 6 charts
  • Finishes in 8.2 min, always under a 4 GB memory cap

How the model works

It reads a user's history in order, decides which past movies matter most, and scores every movie in the catalogue.

5Top 10already-watched movies removed

What we mixed and matched

A model is built from interchangeable parts. We varied two of them and kept the rest fixed.

PartWhat it decidesOptions tested
Layer designHow each building block is arranged Post-LN   Pre-LN   LiGR (gated)
Loss functionHow the model measures its mistakes — and how many wrong movies it compares against BCE (1) · gBCE (256) · Sampled softmax (256) · Full softmax (all 3,706)
Training methodWhat task the model practisesFixed: predict the next movie at every position
Negative samplingWhich wrong movies are comparedFixed: random

3 × 4 = 12 combinations. "LiGR + Sampled softmax" is eSASRec's own recommended combination.

Results

All measured on an NVIDIA RTX 4050 Laptop GPU (6 GB). Accuracy is tested against all 3,706 movies.

½

The main finding: sampled softmax matches full softmax almost exactly while using about half the GPU memory — NDCG@10 0.1736 vs 0.1757, using 1,226 MB vs 2,324 MB, and it recommends a wider range of movies.

What the results say

  1. Sampled softmax is the efficient choice. On average it reaches 94% of full softmax's accuracy using 1.8× less memory — the same loss eSASRec chose.
  2. BCE is cheapest, but too inaccurate. It reaches 73% of sampled softmax's accuracy while saving only about 7% memory.
  3. Full softmax costs the most memory. It's the only loss above 2 GB, and its cost grows with the size of the catalogue.
  4. Post-LN was the best layer design here. It's also the fastest per epoch, so it fit more training into 32 seconds.
  5. eSASRec's own pick came 5th — but that isn't a verdict. LiGR is ~22% slower per epoch, so it trained less, and it was still improving when time ran out.

What we learned while building it

Four problems we found, measured and explained.

Speed

More GPU memory doesn't make training faster

~12× faster per epoch

Beta 0.1 took 3,837 tiny steps per epoch, leaving the GPU idle half the time. The benchmark does the same work in 24 large steps. Proof memory isn't the cause: 1.7 GB and 3.4 GB batches took the same time per epoch.

Bug fixed

Wrong movies must be sampled per user

0.004 → 0.074 NDCG

Sharing one set of 256 wrong movies across a whole batch starved most movies of feedback. Drawing 256 per user fixed it (short trial runs).

Hardware

The CPU core type doubles response time

~1.5 ms vs ~3.2 ms

This laptop's CPU mixes fast and slow cores. The benchmark now runs on the fast ones, but response time still varies — so compare combinations on memory and accuracy, not response time.

Unresolved

gBCE collapsed

recommends ~5% of movies

It collapses with calibration on or off and with 32 or 256 negatives, while sampled softmax — using the same negatives — works. Likely a short-training effect. Not evidence gBCE is worse.

Read before quoting

  • One run each — small differences may be noise.
  • Equal time, not equal training — slower designs got fewer epochs.
  • Half the runs were still improving at 32 seconds.
  • LiGR and gBCE are our own implementations of the papers' descriptions.
  • Not directly comparable to the paper's numbers — different setup and scale.
  • One dataset, one laptop. Larger catalogues would widen the memory gap.
