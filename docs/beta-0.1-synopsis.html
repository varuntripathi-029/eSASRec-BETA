Beta 0.1 predicts the next movie a user will watch from the order of what they watched before. It proves the full data → model → ranking pipeline end to end, with a trained self-attention model, honest full-catalogue evaluation, measured cost and latency, and a browser front end.

What Beta 0.1 does

Given a user's viewing history in order, the model scores every movie in the catalogue and returns the top K it has not already seen. Change the history and the recommendations change — that sensitivity to order is what separates sequential recommendation from ordinary recommendation.

The browser front end has four views: Recommend (build a history, get the top K), Metrics (accuracy, cost and latency, with training curves), Dataset (statistics, distributions and a record browser), and Test on dataset — pick random real users, choose any subset, and run the model through them one at a time against each user's actual next movie.

Evaluation choices that matter

  • Full-catalogue ranking. The held-out item is ranked against all 3,706 items, not against a sample of random negatives. Sampled metrics do not reliably preserve which model is better3, so they are avoided from the start.
  • Seen items masked — a user is never recommended something already in their history.
  • Pessimistic ties and a non-finite check. A degenerate model that scores every item equally cannot record a perfect hit, and NaN output raises an error instead of inflating the score.
  • Latency and throughput measured separately. One query on its own (what a user waits for) versus amortised cost at batch 256 (what an offline evaluation costs).
  • Cross-checked through the live server. Scoring all 6,040 users one request at a time through the web API reproduces the offline Recall@10 exactly (0.2987), so what the front end shows and what the evaluation reports are the same computation.

What the numbers say. Respecting order nearly doubles accuracy (0.2987 vs 0.1618) for 3.8× the training time and 4× the per-query latency — still just over a millisecond, on 85 MB of a 6 GB card. Two caveats: MeanPoolRec is still improving at epoch 5 while the Transformer has plateaued, so the comparison is at equal epochs, not equal convergence. And these are not comparable to the SASRec paper, which ranks against 100 sampled items.

Known limitations

In the results

  • No fixed random seed. A retrain moved test Recall@10 from 0.2969 to 0.2987 (Transformer) and 0.1588 to 0.1618 (MeanPool). The gap between the models dwarfs that, but comparisons separated by 1–2% will need several seeded runs.
  • Popularity bias. A history of animated films returns Prince of Egypt, Anastasia and Mulan; a niche horror history mostly returns Star Wars and American Beauty. Recall@10 cannot see this.

In scope

  • Not yet SASRec. The model is SASRec-shaped but trains on one next-item target per window rather than the shifted-sequence objective.
  • Movies, not music. The guide permits MovieLens for the demo; the architecture is domain-agnostic.
  • Three bugs found and fixed while building: NaN from padded rows spreading across positions; that NaN silently raising the metric through optimistic ties; and a batched throughput figure mislabelled as per-query latency.

Before any of them

  • Seeded, repeated runs with error bars. Several of these promise gains of a few percent, which is inside the run-to-run shift already observed. Without this, no addition can be shown to work.
  • A proper SASRec baseline (guide step 2). Each addition should be measured against SASRec or eSASRec, not against this demo model.
  • Beyond-accuracy metrics — catalogue coverage and a popularity-bias measure, since the bias above is already visible and several additions claim to improve personalisation.
Most demonstrable on this data: #2 (distillation + adaptive sequence length) for cost and latency, paired with #3 (LLM-derived user profiles) for accuracy and the project's generative-AI component. #1, #5 and #7 need a deeper model or a much larger catalogue before their benefit becomes measurable; #4 needs external movie metadata that MovieLens-1M does not ship.
